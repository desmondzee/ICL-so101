# SO-101 multitask Zero-WAM diagnosis tracker

Updated: 2026-09-27

## Question and starting evidence

Can either released Zero-WAM checkpoint select and manipulate the *named* target in a cluttered SO-101 scene without SO-101 training? The red-cube lift is a weak discriminator: the cube is usually in front of the arm and is the only object. The previous [adaptation tracker](so101_adaptation_tracker.md) records 0/3 successful full-length cube lifts for each checkpoint/action-mode baseline. In the new cluttered scene, 46 saved model trials to date have **zero task successes and zero logged grasp steps**; this includes short screens, full-horizon tasks, and ICL video comparisons, not 46 independent seeds.

Here, “joint actions” means five SO-101 arm joint angles plus gripper (`14–18, 28`); “pose actions” means TCP XYZ/quaternion plus gripper (`0–6, 28`). Both use the same executed-motion feedback rules from `zero_wam/so101_eval.py`: pose history is measured TCP motion after IK and stepping, and joint history is measured joint motion. Keep requested-to-realized pose errors.

## Scene and controls

The primary task is `sim/libero_basket_env.py`: alphabet soup and cream cheese are named targets; tomato sauce and ketchup are distractors; basket and objects move among seeds. `sim/scripted.py` supplies a task sanity check. First adapt this scene to a **single named-target pick/lift** and a **single named-target basket placement**, with a paired prompt for each target. This permits target-selection tests without conflating them with the full two-object task. Then evaluate the full `LiberoBasketEnv.task_description` two-object placement. Keep the cube task only as a bridge to prior results.

Before model trials, verify scripted success and reachability for every selected seed and task, including correct-object grasp and placement. Do not treat lower TCP-to-nearest-object distance as success. Record distance to each named object, which object was grasped or moved, target lift, distractor displacement, basket containment, and task success. A null or shuffled instruction with the same scene and model is a target-conditioning control. Pair seeds and object layouts across prompts, checkpoints, and action modes.

## Implementation notes and next action

`zero_wam/so101_eval.py` now supports the basket scene and five named tasks. It logs every object's TCP distance, displacement, lift, grasp, and containment on each control, and defines lift success as a grasp with ≥5 cm vertical displacement; placement requires the named object inside the basket after ≥3 cm displacement. `so101_multitask` entrypoints in both Modal apps accept task, variant list, seeds, and horizon. Local 4-control mock-worker smoke passed for both pose and joint with first-frame snapshots, action traces, videos, and summaries under `/tmp/zero_wam_multitask_smoke/`.

The pinned LIBERO submodule was initialized (`third_party/LIBERO`, `8f1084e`). `zero_wam/so101_multitask_baseline.py` uses `sim/scripted.py` and the same evaluator task conditions: **30/30** soup-only/cheese-only lift and placement and full-basket checks passed on seeds 1, 7, 8 in both pose and joint control under `robot_init_qpos_noise=0`. The joint gate converts scripted pose targets to IK joint commands. Soup lift first succeeded by control 112, cheese by 132, full basket by 568; per-task poses and controller logs are in `outputs/zero_wam/so101/multitask/scripted_baseline.json`. Seed 0 fails cheese-only placement; cube seeds 101–102 fail scripted soup grasp in this scene, so do not use them for scored comparisons.

First live batch: `MUJOCO_GL=egl .venv/bin/python -m zero_wam.modal_cli run zero_wam/modal_{so101_pretrain,app}.py::so101_multitask --task soup_lift --variants pose,joint --seeds 1 --max-steps 128` (invoke each app separately). Logs: `/tmp/so101_multitask_{pretrain,posttrain}_seed1.log`. Paired soup/cheese lift screens on seeds 1, 7, 8 are complete for both checkpoints and action modes with no grasp; cheese seed 1 used 192 controls to exceed its scripted first-success time.

Additional seed-7 pretrain screens for absolute joints, wrist tilt, and basket-only normalization are running (`/tmp/so101_multitask_pretrain_ablations_seed7.log`). This seed starts with soup farther from the TCP than cheese, so it tests whether a configuration can steer toward the named, non-nearest target.
