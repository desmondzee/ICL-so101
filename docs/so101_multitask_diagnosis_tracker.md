# SO-101 multitask Zero-WAM diagnosis tracker

Updated: 2026-09-28

**Pretrain evidence correction:** historical trials used the wrong transformer; the first two exact-load screens also cached predicted targets. Both sets are excluded from policy conclusions. Corrected loading passes strict live checks; fresh executed-feedback testing is active. See current status below.

## Question and starting evidence

Can either released Zero-WAM checkpoint select and manipulate the *named* target in a cluttered SO-101 scene without SO-101 training? The red-cube lift is a weak discriminator: the cube is usually in front of the arm and is the only object. The previous [adaptation tracker](so101_adaptation_tracker.md) records 0/3 successful full-length cube lifts for each checkpoint/action-mode baseline. In the new cluttered scene (`multitask/` plus completed corrected-camera/posttrain-home/pretrain-home trials), 141 saved model trials to date have **zero task successes and zero logged grasp steps**; this includes short screens, full-horizon tasks, and ICL video comparisons, not 130 independent seeds.

Here, “joint actions” means five SO-101 arm joint angles plus gripper (`14–18, 28`); “pose actions” means TCP XYZ/quaternion plus gripper (`0–6, 28`). Both use the same executed-motion feedback rules from `zero_wam/so101_eval.py`: pose history is measured TCP motion after IK and stepping, and joint history is measured joint motion. Keep requested-to-realized pose errors.

## Scene and controls

The primary task is `sim/libero_basket_env.py`: alphabet soup and cream cheese are named targets; tomato sauce and ketchup are distractors; basket and objects move among seeds. `sim/scripted.py` supplies a task sanity check. First adapt this scene to a **single named-target pick/lift** and a **single named-target basket placement**, with a paired prompt for each target. This permits target-selection tests without conflating them with the full two-object task. Then evaluate the full `LiberoBasketEnv.task_description` two-object placement. Keep the cube task only as a bridge to prior results.

Before model trials, verify scripted success and reachability for every selected seed and task, including correct-object grasp and placement. Do not treat lower TCP-to-nearest-object distance as success. Record distance to each named object, which object was grasped or moved, target lift, distractor displacement, basket containment, and task success. A null or shuffled instruction with the same scene and model is a target-conditioning control. Pair seeds and object layouts across prompts, checkpoints, and action modes.

Repeatability check: two pretrain joint soup seed-7 128-control reruns with the same task/config/seed are saved under `outputs/zero_wam/so101/multitask_repeats/{r1,r2}/`.
