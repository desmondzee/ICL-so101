# H3 Max Turbo human demos: first-pass contact-sheet analysis

Reviewed: 2026-09-30 16:27:33 UTC. Model: `minimax/h3-max-turbo/image-to-video` on fal.ai. Prompt version: `v5_exclusion`. Requested duration/resolution: **5 seconds, 480P**, conditioned on the first and last `result_native.png` images from `v4` and `v4_last`.

## Scope and success criteria

The full generation contains **1,960 completed videos across 28 tasks** in [demos_h3_max_turbo](../outputs/robot_removal/demos_h3_max_turbo/). This report manually reviews **84 distinct episodes: three per task**, selected as the first, middle (`floor(n/2)`), and last entries in each task's sorted episode list. These match the original FastH3 first/middle/last samples.

A solid demo requires a plausible intended action and target outcome, **only one hand doing the task**, consistent object identity/inventory and background, and plausible physical contact. Visible people and idle hands are allowed. A second hand manipulating, assisting, stabilizing, or taking over fails. A correct ending alone does not establish success.

Existing contact sheets sample at **2 Hz**. Ten ambiguous clips were additionally inspected using **4 Hz** sheets, including the final sampled frame near 5.0 seconds. Selected supplied endpoint pairs and saved prompts were checked to distinguish model failures from input/prompt conflicts. This is a visual sample review, not continuous video playback or a statistically representative estimate of all 1,960 clips. “No success” below means no success among these three samples, not a claim about the entire task.

## Summary

- **57/84 samples are solid (67.9%); 27/84 fail the stated criteria.**
- **25/28 tasks have at least one solid demo in this review.**
- **12 tasks pass all three samples; 13 are mixed; three have no solid sampled demo.**
- No solid sample: **lower-drawer closing, upper-drawer closing, cable unplugging**.
- Using the previous recorded judgments for the **same 84 FastH3 episodes**, FastH3 scored **38/84 (45.2%)**, covering **19/28 tasks**. H3 Max Turbo gains 19 successful samples and six covered tasks. The old clips were not freshly rescored here; this comparison uses the existing clarified one-acting-hand criterion and saved review. Do not compare this 84-sample rate with the old report's expanded 248-sample rate.

## Diagnosis

### Motion and acting hands

Drawer failures remain concrete mechanism errors: trays are lifted, rotated, removed or brought in from off-screen in place of sliding. Upper-drawer closing/067 has plausible closing motion, but a second hand braces the case, violating the user's single-acting-hand requirement. Upper-drawer opening/001 and 148 also use a supporting hand. Three-block stacking/018 uses both hands to align the final block.

The other sampled three-block stacks (000 and 035) show sequential one-hand placement and release on the 4 Hz recheck. Their offset arrangements are already in the supplied endings; offset alone was not treated as proof of impossible contact. These remain visual assessments, not measured stability tests.

### Input and prompt conflicts

Several failures have causes beyond model selection:

- **Inconsistent hardware/background endpoints:** pen cleanup/040 and 081, Lego/000, marked-cube stacking/000, and cable unplugging/000 and 051 have hardware absent initially and present at the end. Tissue/000 and 141 omit initially visible hardware at the end; the model fulfills this through unrelated hardware removal. Cable/026 already has hardware in both supplied images, yet its generated appearance/transition is inconsistent.
- **Missing manipulated object initially:** tape/000 has no visible roll in the supplied first image; sponge wiping/000 has no visible sponge. The template asks the hand to enter empty and grasp an existing object, but the generated hand brings the missing object into frame.
- **Geometry/appearance mismatch:** pouring/000 grows a spout that is missing from the first image and present in the last. Sandwich/050 gains orange labels without a clear revealing flip; the supplied image pair also differs in package appearance. Sandwich/000 and 025 show one continuous transfer without the duplication seen in some old generations.
- **Incorrect action plan:** color-block/029 has two red blocks and a gray block in the inputs, but its saved prompt explicitly asks for gray onto red, then **black onto gray**. The generated clip introduces a black block and alters the robot background. This is a prompt/input mismatch requiring correction before regeneration.
- **Unsuitable transition:** sock/026 begins with the socks already contained. Its generated action rearranges a contained sock rather than demonstrating clear stowing from the table; it is excluded from the solid handoff list.

First/last conditioning does not guarantee a physically valid path between contradictory images. Hardware changes already demanded by differing inputs are recorded as endpoint conflicts, not attributed solely to model invention.

### Improvements and remaining limits

All three samples pass for shape placement, folding, can transfer, bottle standing, simple brick transfer, one-block box placement, three-block box placement, tape/box transfer, toy/plate transfer, and both slipper tasks, as well as tea transfer. The green shape/000 uses one acting hand and retains its identity; no extra acting arms are observed in the three shape samples.

Tape sliding now has two solid samples (030 and 059). The 4 Hz review of two-shelf slippers/012 confirms a real final pickup/placement between the sparse frames, so it is a success rather than an object-disappearance failure. These corrections show why sparse sheets should be supplemented when an action is ambiguous.

The evidence supports improved sampled coverage with Turbo, while drawers and input consistency still need attention. Before any future regeneration, repair conflicting endpoint pairs and erroneous object/action descriptions, then validate a small varied set. No videos or prompt templates were changed during this review.
